# ALIGNMENT: 文档整理与归档

## 1. 背景与目标
当前 `docs` 目录下存在大量散落的任务文件夹（如 `Docker构建修复`, `Web文件选择器...` 等），导致文档结构混乱，难以索引。
本任务旨在将这些散落的文档文件夹归档到标准的分类目录中，建立清晰的文档层级结构。

## 2. 现状分析
目前 `docs` 目录包含以下顶层分类：
- `01_核心系统`
- `02_功能模块`
- `03_维护与修复`
- `04_测试`

以及大量散落的任务文件夹：
- Docker 相关：`Docker构建修复`, `Docker资源本地缓存`, `Docker适配修复`, `Docker镜像构建修复`, `Docker页面访问修复`, `执行Dockerfile指引`

- 部署相关：`打包项目为exe`
- 测试相关：`构建测试体系`
- 环境相关：`环境配置修复`

## 4. 待确认事项 (Q&A)
- Q: 是否需要保留所有旧的 `TASK_*.md` 等过程文档？
  - A: 是的，本次仅做移动（Move），不删除内容，保留历史记录。
- Q: 移动后是否需要更新文档内的相对链接？
  - A: 这是一个潜在风险点。由于 Markdown 文档中可能引用了图片或其他文档。
  - **策略**: 优先移动文件夹。如果文档中有相对路径引用（如 `../images`），移动层级后会失效。
  - **补救**: 
    - 方案 A: 编写脚本批量修正链接。
    - 方案 B: 仅移动文件夹，后续按需修复链接。
    - **本次决定**: 采用方案 B，但会检查关键的 `README.md` 或引用情况。鉴于大多数任务文件夹是自包含的（图片在文件夹内部），风险较低。如果引用了项目根目录的图片，路径通常是 `../../assets`，层级加深后需要变成 `../../../assets`。
