# ALIGNMENT: RAGFlow集成增强

## 1. 项目上下文分析
Everything2MD 目前是一个本地文档转换工具，支持多种格式转换为 Markdown。核心逻辑已迁移至 Python (`src/core`)，拥有 Tkinter GUI (`src/gui`) 和 FastAPI Web (`web/backend`) 两种界面。
当前 GUI 支持批量转换、并发控制和日志显示。

**目标**: 在现有工具基础上，增加将转换后的文档上传至 RAGFlow 知识库的功能，并支持知识库管理。

## 2. 原始需求与理解

### 2.1 用户故事
> "我选择想要上传到知识库的文档，工具进行转换。转换成功的文档形成一个列表，我从列表中挑选一部分传到我想要放的ragflow的知识库中。剩下的我还能挑选传到另外的知识库中。直到我不想上传或我上传完所有的文件了。"
> "这个过程应该能和文档转换同时进行，所以我需要能看到文档转换的进展。"
> "我还要能配置，文档转换的并发数量。"
> "同时我还能新增知识库。新增知识库可以选择现有的某个知识库作为模板..."
> "整个过程要做好健壮性、可回溯、数据安全和异常处理。"

### 2.2 核心需求分解

1.  **RAGFlow API 集成**:
    *   连接配置：Base URL, API Key。
    *   功能：获取知识库列表、创建知识库（支持模板）、上传文件、启动解析。

2.  **交互流程增强 (GUI)**:
    *   **转换并发配置**: 现有功能，需确保易用。
    *   **转换与上传并行**: 转换任务在后台运行，转换完成的文件实时进入“待上传列表”。
    *   **待上传列表管理**:
        *   显示文件状态（已转换、上传中、已上传、失败）。
        *   多选文件。
        *   操作：选择目标知识库 -> 执行上传。
    *   **知识库管理**:
        *   新建知识库：输入名称，选择“模板知识库”（复制其配置）。

3.  **非功能需求**:
    *   **健壮性**: 网络重试、错误提示、断点续传（可选，或仅重试）。
    *   **可回溯**: 详细日志记录。
    *   **数据安全**: API Key 不明文显示（掩码），建议通过环境变量或加密存储（用户提示用 .env，GUI 可保存在本地配置但需注意安全，或每次输入）。*决策：保存到本地配置 config.json，但提示用户风险或仅在运行时输入？考虑到便利性，通常保存在本地。用户规则提到“API KEY放到 .env 文件中”，但这是针对代码库。对于编译后的 EXE 用户，需要 GUI 配置。我们将支持 GUI 配置并保存到 config.json (明文或简单混淆)。*

## 3. 智能决策与策略

### 3.1 架构策略
*   **Client 层**: 新增 `src/core/ragflow_client.py`，封装 RAGFlow API 交互。使用 `httpx` 实现异步/同步调用。
*   **GUI 层**:
    *   在 `Everything2MDGUI` 中增加 "RAGFlow" 选项卡或扩展现有界面。
    *   建议采用 **"转换监控与分发"** 面板。左侧/上方显示转换进度，右侧/下方显示“已完成文件池”。
    *   用户在“已完成文件池”中勾选文件，底部选择“目标知识库”，点击“上传”。

### 3.2 关键决策点 (自问自答)
*   **Q: 如何实现“以现有知识库为模板”？**
    *   A: 调用 `GET /kb/list` 获取列表，用户选择一个作为模板。调用 `GET /kb/{id}` 获取详细配置（parser_config, embedding_model 等），在调用 `POST /kb/create` 时填入这些参数。
*   **Q: 转换和上传如何并行？**
    *   A: 转换使用现有的 `ThreadPoolExecutor`。转换完成的回调函数 (`on_file_converted`) 将文件路径添加到 GUI 的“待上传列表”中。上传操作也是异步的，不阻塞主界面。
*   **Q: API Key 存储？**
    *   A: 在 GUI 设置中提供输入框。保存至 `config.json`。

## 4. 疑问澄清
*   **RAGFlow API 地址**: 默认为官方云服务地址还是本地部署？ -> 需提供 Base URL 配置项，默认可留空或指向 localhost。
*   **解析启动**: 上传后是否自动启动解析？ -> 需求提到“上传并启动解析”，因此默认为上传后立即调用 parse API。

## 5. 验收标准
1.  **配置**: 能在 GUI 中设置 RAGFlow URL 和 API Key，并测试连接。
2.  **转换**: 转换过程正常，进度条准确，并发数可配。
3.  **列表**: 转换成功的文件实时出现在列表中。
4.  **上传**:
    *   能选择一个或多个文件。
    *   能从下拉框选择目标知识库。
    *   点击上传后，文件上传成功并触发解析。
    *   界面显示上传进度/结果。
5.  **知识库管理**:
    *   能列出所有 KB。
    *   能新建 KB，并成功复制选中模板 KB 的配置。
6.  **异常处理**: API 失败有明确报错，支持重试。
