# CONSENSUS: RAGFlow集成增强

## 1. 最终共识
经过分析与自我决策，我们达成以下共识：

### 1.1 核心功能
1.  **RAGFlow 客户端集成**: 实现完整的 RAGFlow API 客户端，支持连接管理、知识库操作和文档处理。
2.  **流式分发工作流**:
    *   **阶段一 (转换)**: 本地文档 -> Markdown (并发处理)。
    *   **阶段二 (分发)**: 转换完成的文件流式进入“待分发池”，用户可随时挑选文件上传至不同知识库。
    *   **阶段三 (上传与解析)**: 自动上传并触发 RAGFlow 解析。

### 1.2 用户界面 (GUI) 变更
*   **新增 "RAGFlow配置"**:
    *   API Base URL (默认 `http://localhost:9380`)
    *   API Key
*   **新增 "分发中心" 面板**:
    *   **左侧**: 转换任务监控 (进度、日志)。
    *   **右侧**: 待上传文件列表 (文件名、转换状态、上传状态)。
    *   **底部操作区**:
        *   目标知识库下拉框 (含 [新建...] 选项)。
        *   [上传并解析] 按钮。

### 1.3 技术方案
*   **HTTP 客户端**: 使用 `httpx` 库。
*   **并发模型**: 
    *   转换: `concurrent.futures.ThreadPoolExecutor` (现有)。
    *   上传: 异步任务或线程池，确保不阻塞 UI。
*   **数据流**: `ConversionEngine` -> `Queue` -> `GUI List` -> `User Selection` -> `RAGFlowClient` -> `RAGFlow Server`.

## 2. 边界限制
*   **仅支持 GUI**: 本次迭代仅在 Tkinter GUI 中实现，暂不涉及 Web 端。
*   **文件类型**: 仅上传转换成功后的 Markdown 文件（或其他 Everything2MD 输出格式）。
*   **API 版本**: 适配 RAGFlow v1 API。

## 3. 验收标准
*   [ ] 配置 RAGFlow 连接成功。
*   [ ] 转换过程中文件实时显示在分发列表。
*   [ ] 能够创建新知识库（基于模板）。
*   [ ] 能够将文件上传至指定知识库并看到成功状态。
*   [ ] 异常情况（如网络断开）有清晰的错误提示。
