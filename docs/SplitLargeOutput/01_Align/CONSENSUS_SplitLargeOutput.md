# CONSENSUS: 大文件自动切分策略

## 1. 核心共识

### 1.1 需求定义
- 系统需具备检测输出文件大小的能力。
- 当输出文件超过设定阈值（MB）时，自动将其拆分为多个小文件。
- 拆分后的单个文件大小应小于阈值的 90% (留出缓冲空间)。
- 拆分应尽量保持 Markdown 语义（按行拆分）。

### 1.2 技术规范
- **配置项**: `max_output_file_size_mb` (整数，单位 MB)。
    - 默认值: `50` (MB)。
    - 若设置为 `0` 或负数，则禁用此功能。
- **拆分逻辑**:
    - 计算 `target_size_bytes = max_output_file_size_mb * 1024 * 1024 * 0.9`。
    - 逐行读取源文件，写入 `filename_partX.md`。
    - 当当前分卷大小超过 `target_size_bytes` 时，完成当前行写入后，切换到下一个分卷。
    - 拆分完成后，**删除** 原始大文件。
- **文件命名**:
    - 原文件: `Report.md`
    - 拆分后: `Report_part1.md`, `Report_part2.md`, ...

### 1.3 影响范围
- **代码模块**:
    - `src/core/config.py`: 新增配置项。
    - `src/core/engine.py`: 调用拆分逻辑。
    - `src/core/utils.py` (或新模块): 实现拆分算法。
    - `src/gui/fixed_main_v2.py`: (可选) 界面增加配置输入框。鉴于当前任务主要是策略补充，暂不强制要求 GUI 变更，但应在 Config 中预留。
- **用户感知**: 用户在输出目录看到的不再是打不开的巨型文件，而是多个分卷。

## 2. 验收标准
1.  **配置生效**: 修改配置文件中的阈值，程序能正确读取。
2.  **触发拆分**: 构造一个大于阈值的文件（如 10MB，阈值设为 5MB），转换后应生成 `_part1`, `_part2`, `_part3`。
3.  **大小合规**: 每个分卷大小均小于 `阈值 * 0.9` (在单行不过大的前提下)。
4.  **内容完整**: 所有分卷内容拼接后应与原文件一致（可通过 MD5 校验拼接后的内容）。
5.  **原始清理**: 原大文件不存在于输出目录。

## 3. 风险评估
- **断行风险**: 按行切分可能截断跨行的 Markdown 语法（如代码块）。
    - *缓解*: 这是一个已知限制。为了通用性和性能，暂不进行复杂的语法解析。对于大多数文档（Office 转 MD），行通常对应段落，风险较低。
- **文件覆盖**: 如果目录下已有 `_part1` 文件，可能会被覆盖。
    - *策略*: 覆盖现有文件（符合常规转换逻辑）。
