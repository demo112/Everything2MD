# LibreOffice启动超时修复 - 评估总结

## 1. 修复总结
本次修复解决了 `subprocess.Popen` 接收不支持参数 `timeout` 导致的程序崩溃问题。通过分离参数传递，确保了 `timeout` 正确应用于 `communicate` 方法。

## 2. 质量评估
- **代码质量**：修复逻辑清晰，未引入复杂性。
- **测试质量**：新增了针对底层辅助方法的专用单元测试，填补了之前的测试空白。
- **文档质量**：完整记录了问题分析、修复方案和验收结果。

## 3. 经验教训（举一反三）
- **不要盲目相信 Mock**：之前的测试通过是因为 Mock 对象没有模拟 `Popen` 对参数的严格校验。应当尽量减少对被测系统内部实现的 Mock，或者确保 Mock 行为与真实对象一致。
- **辅助方法也需要测试**：像 `_run_subprocess` 这样处理底层系统调用的辅助方法，虽然被业务逻辑调用，但由于业务逻辑测试往往关注业务结果，容易忽略底层调用的参数细节。应为这些辅助方法编写独立的单元测试，覆盖各种参数组合。
- **参数传递审查**：在封装标准库调用时，必须严格查阅文档，确认每个参数的适用范围（如 `timeout` 适用 `run/wait/communicate` 但不适用 `Popen` 构造函数）。

## 4. 遗留问题
- `OfficeConverter` 和 `PptConverter` 中存在 `_run_subprocess` 的代码重复。建议在未来的重构中将其提取到 `BaseConverter` 或公共 Mixin 中。
