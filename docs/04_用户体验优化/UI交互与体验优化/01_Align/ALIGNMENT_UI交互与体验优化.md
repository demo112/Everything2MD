# ALIGNMENT_UI交互与体验优化

## 原始需求
1. 点击取消以后，一直没有停止，加一个取消后超时杀死进程的逻辑。
2. 保存配置后，界面无现象。不友好。
3. 分发中心的多选按钮，不友好，看着是个文本拼起来的。
4. 新建KB，要改成新建知识库。

## 需求理解与分析

### 1. 取消转换的超时强制终止
- **现状**: 目前点击"取消"仅设置停止标志位 (`stop_flag`)，如果底层转换进程 (LibreOffice/Pandoc) 正在执行阻塞操作，线程无法立即响应停止信号，导致界面看似无反应。
- **目标**: 实现"软停止" + "硬终止" 机制。点击取消后尝试软停止，若一定时间（如 3秒）后任务仍未结束，则强制杀死相关的子进程。
- **技术点**: 需要追踪每个转换任务关联的子进程句柄 (Popen object)，并提供 `abort()` 或 `kill()` 接口。

### 2. 保存配置反馈
- **现状**: 点击"保存配置"按钮后，后台执行了保存逻辑，但界面无任何提示，用户不确定是否成功。
- **目标**: 添加 `messagebox.showinfo` 提示"配置已保存"。

### 3. 分发中心多选 UI 优化
- **现状**: 使用 `[x]` 和 `[ ]` 文本模拟复选框，视觉效果粗糙。
- **目标**: 优化视觉体验。由于使用的是 `ttk.Treeview`，无法直接嵌入原生 Checkbox 控件。
- **方案**: 使用 Unicode 符号 `☑` (U+2611) 和 `☐` (U+2610) 替代纯文本，提升视觉识别度。

### 4. 文本修正
- **现状**: 按钮文本为 "新建KB..."。
- **目标**: 修改为 "新建知识库..." 以符合中文语境和全称规范。

## 疑问澄清
- **Q1**: 强制杀死进程是否会影响系统其他 LibreOffice 实例？
  - **A1**: 我们将尝试仅杀死由当前转换任务启动的子进程（通过追踪 Popen 对象）。如果无法精确追踪，考虑到 Windows 环境下 `taskkill` 的风险，我们将优先采用精确追踪方案。
- **Q2**: 多选按钮是否需要重构为其他控件？
  - **A2**: 考虑到维护成本和现有架构，仅优化显示符号是最快且低风险的方案。

## 智能决策策略
- **取消逻辑**: 采用 `CancellationContext` 模式，将进程句柄传递给 Engine 管理，实现精确查杀。
- **UI 反馈**: 使用标准 Tkinter 对话框。

## 最终共识
1. **实现强制终止**: 修改 `ConversionEngine` 和 Converter 类，支持关联 Popen 对象并提供 `abort` 方法。
2. **优化 UI 细节**: 修正文本，增加反馈，美化复选框符号。
