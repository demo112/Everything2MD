# ALIGNMENT: 带上下文的图片解析

## 1. 项目背景

Everything2MD 目前已经具备了使用多模态 LLM 对文档中的图片进行识别和描述的功能。然而，目前的实现仅发送图片本身，忽略了图片在文档中的上下文信息。

## 2. 需求理解

### 2.1 原始需求

用户希望在图片解析时，携带图片所在文档前后的上下文信息。 思路：使用图片所在位置前后一定长度的文字作为其上下文。

### 2.2 核心价值

-   **提高准确性**：文档中的图片往往与周围的文本紧密相关（如“如下图所示...”、“表 1 显示了...”）。提供上下文可以帮助 LLM 更准确地理解图片的意图和内容。
-   **消歧**：对于一些含糊不清的图片，上下文提供了关键的解释线索。

### 2.3 功能规范

1.  **上下文提取**：
    -   在解析 Markdown 文档查找图片时，同时提取图片标签 `![alt](path)` 前后的文本。
    -   提取范围：默认前后各 500 个字符（可配置或硬编码默认值）。
    -   处理边界情况：文件开头或结尾不足指定长度时，取实际可用长度。
2.  **API 交互**：
    -   更新发送给 LLM 的 Prompt，加入提取到的上下文文本。
    -   Prompt 需明确指示 LLM 参考上下文来生成描述。
3.  **配置**：
    -   新增配置项 `img_context_length` (默认 500)，控制上下文提取长度。

## 3. 歧义与疑问

-   **Q1**: 上下文是否需要过滤 Markdown 标记？
    -   **决策**: 不需要严格过滤。保留 Markdown 标记（如标题、列表）反而有助于 LLM 理解文档结构。
-   **Q2**: 如果图片连续出现，上下文是否会包含其他图片的标签？
    -   **决策**: 是的，这没问题。LLM 可以处理。
-   **Q3**: 上下文过长会导致 Token 消耗增加。
    -   **决策**: 默认 500 字符是一个平衡点。用户可以通过配置调整。

## 4. 关键决策点

-   **上下文注入位置**: 在 System Prompt 或 User Message 中增加 `Context` 字段。
-   **实现方式**: 修改 `ImageRecognizer._process_markdown_async` 中的遍历逻辑，计算切片索引。

## 5. 最终共识

-   **目标**: 修改 `src/core/image_recognition.py`，实现上下文提取和 Prompt 注入。
-   **交付物**: 更新后的代码，以及通过测试验证上下文确实被发送并提升了效果（或至少没报错）。
