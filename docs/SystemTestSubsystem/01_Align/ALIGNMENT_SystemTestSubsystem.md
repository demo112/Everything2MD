# ALIGNMENT_SystemTestSubsystem

## 1. 项目上下文分析

### 1.1 现有架构
- **核心语言**: Python (核心逻辑, GUI) + Shell (模块化脚本)。
- **测试框架**:
    - Python: `pytest` (配置在 `pytest.ini`)。
    - Shell: `bats` (内置在 `test/bats` 目录)。
- **目录结构**:
    - `test/`: 主要测试目录，包含 `unit`, `integration`, `ui`, `bats`, `fixtures`。
    - `tests/`: 遗留或误用的测试目录，仅包含 `verify_config_persistence.py`。
    - `scripts/run_tests.ps1`: Windows 测试运行脚本。
- **环境约束**: 用户明确要求虚拟环境命名为 `.venv`，但现有脚本硬编码为 `venv`。

### 1.2 现有问题
1.  **目录分散**: `test/` 和 `tests/` 共存，导致维护混乱。
2.  **环境不一致**: 脚本使用 `venv`，规则要求 `.venv`。
3.  **测试策略不明确**: 缺乏统一的“系统测试”定义，目前的 `run_tests.ps1` 混合了不同层级的测试，但没有明确的系统级验收流程。
4.  **依赖限制**: `bats` 测试依赖 Git Bash，在 Windows 环境下运行需要特定配置。

## 2. 需求理解确认

### 2.1 核心目标
将“系统测试”作为一个独立的子系统进行分析和设计，包含两个核心功能：
1.  **检查测试策略与用例**: 评估现状，修复不合理之处（如目录结构、环境配置）。
2.  **执行完整系统测试**: 提供可靠的自动化执行机制，覆盖所有层级。

### 2.2 范围定义
- **输入**: 现有的代码库、测试用例、测试脚本。
- **输出**:
    - 统一的测试目录结构。
    - 修正后的测试运行脚本（适配 `.venv`）。
    - 完整的测试执行报告。
    - 修复发现的任何环境或配置问题。

### 2.3 关键决策点 (自决)
- **决策 1**: 将 `tests/` 目录下的内容迁移至 `test/`，并删除 `tests/` 目录。
    - *理由*: 保持目录结构整洁，符合 `pytest.ini` 配置。
- **决策 2**: 修改 `scripts/run_tests.ps1` 以支持 `.venv`。
    - *理由*: 符合用户明确的环境规则。
- **决策 3**: 将“系统测试”定义为运行所有现有的 Unit, Integration, 和 UI 测试，并确保通过。
