# CONSENSUS_SystemTestSubsystem

## 1. 最终共识

### 1.1 需求描述
建立一个健壮的“系统测试子系统”，负责维护测试架构的合理性并执行全量测试。该子系统不仅是运行脚本，还包含对测试环境和结构的治理。

### 1.2 验收标准
1.  **结构统一**: 项目中只存在一个 `test/` 目录，所有测试用例均位于其中。
2.  **环境适配**: 所有测试脚本均使用 `.venv` 虚拟环境。
3.  **一键执行**: 提供单一入口（如优化后的 `run_tests.ps1` 或新脚本），能成功运行 Python 和 Bats 测试。
4.  **结果验证**: 能够生成清晰的测试报告，并验证所有测试通过。

### 1.3 技术方案
1.  **目录重构**:
    - 移动 `tests/verify_config_persistence.py` 到 `test/integration/` (或其他合适位置)。
    - 删除 `tests/`。
2.  **脚本优化**:
    - 修改 `scripts/run_tests.ps1`:
        - 将 `venv` 替换为 `.venv`。
        - 增强对 Python 路径的探测 (`py -3`, `python` 等)。
        - 确保 `bats` 测试能正确调用 Git Bash。
3.  **测试执行**:
    - 使用优化后的脚本执行全量测试。
    - 记录执行日志。

### 1.4 边界限制
- 不重写现有的业务代码，仅在测试发现 Bug 时进行修复（或记录）。
- 不引入新的重型测试框架，沿用 `pytest` 和 `bats`。
