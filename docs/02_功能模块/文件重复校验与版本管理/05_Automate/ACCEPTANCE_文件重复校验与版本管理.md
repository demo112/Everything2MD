## 2. 功能验收 (代码走查与模拟验证)
### 2.1 一致性校验
- **场景**: 上传已存在且内容未变的文件。
- **逻辑实现**:
  - 解析文件名获取 clean basename。
  - 检查知识库中是否存在同名（忽略版本号）文件。
  - 对比本地 Hash 与远程版本 Hash。
  - 如果一致，日志记录 "跳过已存在的文件(Hash一致)"，不执行上传。
- **状态**: 代码已实现 (src/gui/main.py)，逻辑正确。

### 2.2 版本更新与清理
- **场景**: 修改本地文件内容后重新上传。
- **逻辑实现**:
  - 检测到 Hash 变更。
  - 标记旧版本为待删除。
  - 调用 `delete_documents` 接口删除旧版本文档。
  - 清理本地旧版本文件（`_vHash` 命名的副本）。
  - 重命名本地文件为新版本名 `name_vNewHash.ext`。
  - 上传新文件。
- **状态**: 代码已实现 (src/gui/main.py)，已修复双重版本号命名的潜在 Bug。

### 2.3 命名规范
- **场景**: 上传文件。
- **逻辑实现**:
  - 始终将文件重命名为 `{basename}_v{Hash}.{ext}` 格式。
  - 确保知识库和本地存储中版本标识清晰。
- **状态**: 代码已实现 (src/gui/main.py)。
