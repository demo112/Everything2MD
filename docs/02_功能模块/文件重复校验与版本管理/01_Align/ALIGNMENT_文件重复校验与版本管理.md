# ALIGNMENT: 文件重复校验与版本管理

## 1. 原始需求
用户要求迭代文件重复判断逻辑，加入一致性校验：
1.  **一致性校验**：如果新文档与之前的不一样（内容变更），就要进行转换或上传分析，而不是跳过。
2.  **旧文档清理**：同步的，要在本地和知识库清除掉旧的文档。
3.  **版本标识**：在名称后缀中体现其版本差异。

## 2. 现状分析
### 2.1 现有上传逻辑
- 目前 `src/gui/main.py` 中的 `_bg_upload` 方法仅基于**文件名**进行去重。
- 如果知识库中已存在同名文件，直接跳过。
- 无法感知文件内容的变更（如修正了错别字或更新了段落）。

### 2.2 技术挑战
- **内容比对**：需要一种高效的方式比对本地文件和知识库文件是否一致。
- **版本管理**：需要在文件名中嵌入版本信息，同时保持可读性。
- **原子性操作**：删除旧文件和上传新文件应尽可能接近原子操作，避免中间状态导致的数据丢失。

## 3. 需求理解与确认
### 3.1 核心流程
1.  **计算指纹**：对本地待上传文件计算 MD5 哈希。
2.  **检索现状**：查询 RAGFlow 知识库中是否存在“同名但不同哈希”的文件。
3.  **决策执行**：
    - 若不存在同名文件 -> 直接上传（带哈希后缀）。
    - 若存在同名且哈希一致 -> 跳过（无需更新）。
    - 若存在同名但哈希不一致 -> 删除旧文件 -> 上传新文件（带新哈希后缀）。

### 3.2 命名规范
- 采用 `文件名_v{Hash8}.扩展名` 的格式。
- 例如：`需求文档_va1b2c3d4.docx`。

## 4. 关键决策点
- **哈希算法**：选择 MD5，取前 8 位。既能保证足够碰撞安全性（对于文档管理场景），又能保持文件名长度可控。
- **删除策略**：默认自动删除旧版本，保持知识库整洁。
