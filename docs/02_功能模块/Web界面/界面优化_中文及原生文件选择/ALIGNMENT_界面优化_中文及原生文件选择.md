# ALIGNMENT: 界面优化_中文及原生文件选择

## 1. 原始需求
*   **文件选择**：弃用当前的自定义Web模态框，改用“浏览器或系统”的选择框。
*   **语言**：界面完全中文化。

## 2. 现状分析
*   **架构**：Web前端 (HTML/JS) + Python后端 (FastAPI) + Shell脚本核心 (main.sh)。
*   **当前文件选择**：前端通过 API 获取文件列表，在自定义模态框中展示。
*   **当前语言**：全英文。
*   **运行环境**：本地运行 (Localhost)，Windows环境。

## 3. 技术方案对齐
### 3.1 文件选择方案
*   **挑战**：浏览器 `<input type="file">` 出于安全原因无法获取文件的完整本地绝对路径（返回 `C:\fakepath\...`）。后端 `main.sh` 需要绝对路径来读取文件。
*   **选项 A (Upload)**：前端上传文件 -> 后端存临时目录 -> 处理。缺点：大文件慢，且无法处理“输出目录”选择（浏览器无法选择输出路径供后端写入）。
*   **选项 B (System Dialog)**：后端调用 `tkinter` 或 `easygui` 弹出系统原生文件对话框。优点：直接获取绝对路径，体验最接近原生应用，支持文件和文件夹选择。前提：用户在服务端本机操作（符合现状）。
*   **结论**：采用 **选项 B**。后端新增 API `/api/select-path`，调用系统对话框。

### 3.2 中文化方案
*   **HTML**：直接替换所有英文文本为中文。
*   **JS**：替换 Alert、Status 提示信息为中文。
*   **后端**：日志信息暂保持现状或仅关键信息中文化（主要关注前端展示）。

## 4. 待确认问题
*   无。假设用户运行在本地桌面环境，支持弹出窗口。

## 5. 结论
*   目标明确，技术路径可行。
*   输出：修改后的 `index.html`, `script.js`, `main.py`。
