# CONSENSUS: Image Recognition (解析增强)

## 1. 需求共识

### 1.1 核心功能

在现有的文档转 Markdown 流程中，增加 **图片识别与解析** 功能。
- **输入**: Office 文档 (Word/PPT)、PDF 等包含图片的文档。
- **处理**:
    1. 提取文档中的图片。
    2. 调用用户配置的多模态大模型 (Multimodal LLM) 对图片进行内容识别。
    3. 将识别出的文本内容插入到 Markdown 文档中图片对应的位置。
- **输出**: 包含图片描述信息的 Markdown 文件。

### 1.2 用户界面 (UI)

-   **目标平台**: Desktop GUI (`src/gui/main.py`)。
-   **变更**: 增加第三个页签 "解析增强" (Parsing Enhancement)。
-   **配置项**:
    -   **模型配置**: Base URL, API Key, Model Name (OpenAI 兼容格式)。
    -   **并发控制**: 单次对话处理一张图片，但支持多线程/异步并发请求（用户可配置最大并发数）。

### 1.3 技术策略

-   **参考 RAGFlow**: 将图片内容转化为文本，以增强检索效果。
-   **处理流程**:
    1.  **转换阶段**: 使用 LibreOffice/Pandoc 转换文档，同时提取图片到临时目录。
    2.  **解析阶段**: 扫描生成的中间文件 (HTML 或 Markdown)，找到图片引用。
    3.  **识别阶段**: 使用 `asyncio` 并发调用 LLM API 处理图片。
    4.  **注入阶段**: 将 LLM 返回的描述文本插入到 Markdown 中（例如作为引用块或紧随图片后的文本）。
-   **Docker 适配**: 确保 Docker 容器内环境支持新增的依赖 (如有)，且用户需重建容器。

## 2. 边界与限制

-   **并发限制**: 受限于用户配置和 API 限制。
-   **图片格式**: 支持常见格式 (JPG, PNG)。
-   **错误处理**: 图片识别失败不应中断整个文档转换，应记录错误并保留原图片标记。
-   **成本**: 用户需自行承担 LLM API 调用成本。

## 3. 验收标准

1.  **UI**: 成功显示 "解析增强" 页签，并能保存/加载配置。
2.  **功能**: 转换带图 Word/PPT 时，Markdown 结果中包含图片内容的文字描述。
3.  **并发**: 日志显示图片是并发处理的（通过时间戳或日志顺序验证）。
4.  **配置**: 修改配置能生效（如切换模型或并发数）。
5.  **稳定性**: 即使网络不通或 API 报错，文档转换仍能完成（仅缺失图片描述）。

## 4. 待确认项

-   **插入位置**: 默认插入在图片下方，格式为 `> **图片描述**: [内容]`。
-   **图片存储**: 原始图片是否保留取决于原有的转换逻辑（通常 Pandoc 会处理），本功能侧重于**增加文本**。
